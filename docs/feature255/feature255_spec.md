# Подробный технический контракт

## 1. Контракт инфраструктурных адаптеров

| Адаптер | Сигнатура | Возврат |
|---|---|---|
| `IdempotencyBegin` | `@OperationId VARCHAR(64), @OperationType VARCHAR(20), @AccountFrom VARCHAR(20), @AccountTo VARCHAR(20), @Amount DECIMAL(18,2), @Status TINYINT OUT, @PreviousResultCode INT OUT` | `0`; `-3000` нет ключа; `-3003` ключ с другими параметрами; `-3002` некорректное состояние |
| `IdempotencyComplete` | `@OperationId VARCHAR(64), @ResultCode INT` | `0`; `-3002` если нет активной записи `P` |
| `LockTransferAccounts` | `@AccountFrom VARCHAR(20), @AccountTo VARCHAR(20)` | `0` |
| `HandleTransferBusinessError` | `@ErrorCode INT, @OperationId VARCHAR(64), @AccountFrom VARCHAR(20), @AccountTo VARCHAR(20), @Amount DECIMAL(18,2)` | `0` |
| `HandleIdempotencyConflict` | `@OperationId VARCHAR(64), @ErrorCode INT` | `0` |
| `WriteBusinessLog` | `@OperationType VARCHAR(20), @OperationId VARCHAR(64), @AccountFrom VARCHAR(20), @AccountTo VARCHAR(20), @Amount DECIMAL(18,2), @ResultCode INT` | `0` |
| `WriteIdempotentReplayLog` | `@OperationId VARCHAR(64), @PreviousResultCode INT` | `0` |
| `LogSystemError` | `@ErrorNumber INT, @ErrorMessage NVARCHAR(4000), @OperationId VARCHAR(64), @AccountFrom VARCHAR(20), @AccountTo VARCHAR(20), @Amount DECIMAL(18,2)` | `0` |

Требования:

- адаптеры не коммитят и не откатывают внешнюю транзакцию;
- выполняются внутри транзакции вызывающей стороны;
- не бросают исключения вместо возврата кода;
- непредвиденные сбои логируются, но не ломают контракт.

## 2. Порядок выполнения `procTransferMoney`

1. Проверка `OperationId`.
2. Проверка `N1`, `N2`.
3. Проверка `S > 0`.
4. Проверка запрета перевода на тот же счет.
5. Начало транзакции.
6. Публикация/проверка идемпотентного ключа.
7. Блокировка счетов.
8. Проверка существования счетов и наличия средств.
9. Списание со счета отправителя.
10. Зачисление на счет получателя.
11. Запись бизнес-журнала.
12. Завершение операции в реестре идемпотентности.
13. Коммит и возврат результата.

## 3. Варианты статусов идемпотентности

| Статус | Значение | Интерпретация |
|---|---|---|
| `0` | новый | операция только зарегистрирована |
| `1` | завершен | предыдущая операция успешно завершена |
| `2` | выполняется | конфликт/параллельное выполнение |

Сценарии:

- `1` => вернуть `PreviousResultCode` и/или `1` для повторного успешного вызова;
- `2` => вернуть `-3001` и зафиксировать конфликт;
- некорректный ответ адаптера => `-3002`.

## 4. Контракт по тестам

### Unit-тесты

Проверяются ветки отказа и повторных вызовов на заглушках.

### Contract-тесты

Проверяются сценарии против реальной инфраструктуры `oper`:

- корректность параметров вызова;
- отсутствие необработанных статусов `0`, `1`, `2`;
- завершение `IdempotencyComplete`;
- атомарность реестра и журналов;
- совпадение поведения с рабочей инфраструктурой.

## 5. Правила именования

- все имена — простые идентификаторы;
- для схемы фичи используется `featureN`;
- для тестовой схемы — `test_featureN`;
- пустышки и рабочие адаптеры имеют одинаковые имена в разных схемах;
- в коде не используются квадратные скобки.

## 6. Промоушен в prod

```text
1. Оба набора тестов зелены.
2. Заменить ссылки feature255 -> oper в скрипте фичи.
3. Выполнить деплой новой редакции в `oper`.
4. Удалить синонимы-порты из `feature255`.
5. Удалить схемы `feature255` и `test_feature255` после закрытия фичи.
```
